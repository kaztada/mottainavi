# 品目名に英訳を足す

英語モードで品目名を英語で出すための手順。市のデータに英語名は無いので、こちらで訳を足す。優先順位は **誤案内ゼロ > 月額0円 > 1人で維持できること**。訳は表示と英語の検索に使うだけで、区分と注意文言は市のデータどおりに出る。

Kaz が決めるのは **「要確認」の品目の訳** と **本番へのマージ** だけ。Kaz はエンジニアではないので、報告は平易な日本語で書く。

始める前に、記憶ファイル(items-en-translation-trial / release-via-pr / session-rollover)と `docs/data-model.md` §25(訳の決まり)を読む。進み具合は記憶ファイルの末尾と `docs/roadmap.md`「品目名の英訳の追加」にある。

## 仕組み(前提)

- 辞書は2つ。**共通辞書** `data/i18n/items.en.json` と、**自治体の辞書** `data/municipalities/<slug>/items.en.json`(自治体側が優先)。どちらも `{ "品目名": "English name" }`
- 品目名は、全角・半角の括弧や空白の違いを吸収して引く(`itemNameKey`)。共通辞書に入れた訳は、同じ品目名のある他の市にも付く
- 同じ品目名でも市によって区分は違うが、物が同じなら訳は共通でよい(花火は市によって「収集しない」「燃やすごみ」)
- **置き場所の決まり**: ふつうの訳は共通辞書へ。区分や注意点から意味を補った訳(`Battery (car battery etc.)` など)と、意味が確定できない品目の訳は、自治体の辞書へ入れて「要確認」にする
- 作業用のファイルは `work/items-en/`(コミットしない)

## 1. 未訳の一覧を出す

```
git switch -c feat/items-en-<slug> --no-track origin/main
npm run items-en -- todo <slug> [--limit 900]
```

`work/items-en/<slug>.todo.tsv` に、英訳が無い品目が ID・品目名・区分・注意点(定型文は省略)・似た品目の既存の訳・同じ品目名がある他市とその区分つきで出る。**1回の PR は最大900件を目安**にし、多い市は `--limit` で分ける。

## 2. 訳す

`work/items-en/<slug>.en.tsv` に、1行ずつ「ID(タブ)英訳(タブ)要確認の理由(あれば)」で書く。理由を書いた行は自治体の辞書に入り、Kaz に見てもらう一覧に載る。

訳の決まり(`docs/data-model.md` §25。迷ったらここを読み直す):

1. 品目名だけを訳す。出し方・区分の情報は足さない
2. 括弧内の条件(大きさ・素材・「PCBなし」など)は落とさない
3. 文頭だけ大文字、補足は括弧、言い換えは ` / `。文字は ASCII
4. 日本特有のものはローマ字と説明を並べる(英語に定着した名があれば英語を先)
5. 米語を基本にする。英米で語が割れるものは両方を並べてよい
6. 品目名だけでは意味が割れるものは、区分と注意点から判断して括弧で補い、**理由を書いて要確認にする**

気をつけること:

- 「似た品目の既存の訳」の訳語にそろえる(同じ物に別の訳語を当てない)
- 同じ品目名が他市にもあるときは、その市の区分を見て同じ物を指しているか確かめる。区分が大きく違って別の物に見えるときは、理由を書いて自治体の辞書に入れる
- 収集しない品目が、収集する別の品目と同じ訳に見えないようにする(車のバッテリーと乾電池)
- 何を指すか分からない品目は、推測で具体的にしない。中立な訳にして理由を書く(市への確認事項として記録する)

## 3. 辞書に入れて点検する

```
npm run items-en -- apply <slug>     # 書き方を点検して辞書に入れる(問題があれば止まる)
npm run items-en -- check            # 付与率と、当たらないキー・書き方の問題
```

## 4. 別の目で読み直す

サブエージェント1体(700件を超えるときは2体)に、品目名・区分・注意点・英訳の一覧を渡して全件を読み直してもらう。渡すもの: 訳の決まり6項目、見てほしい点(誤訳、条件の欠落・付け足し、取り違えそうな訳、不自然な英語)、要確認にした ID。好みの違いは挙げない、確信度を付ける、ファイルは編集しない、と書く。

指摘の採否は自分で決める。採用したものを `en.tsv` に反映して、もう一度 `apply` する。

## 5. 検証

```
npm run build-data -- --all          # MOTTAINAVI_OFFLINE=1 を付ける(市のサイトへアクセスしない)
npm run items-en -- bump             # 品目データが変わった市の data_version を上げる
```

- **共通辞書に足した訳は他市の同名の品目にも付く**ので、その市の版番号も上がる。`data_fetched_at` は変えない
- コミットしてから `npm run build-data -- --all` → `npm run check-data`。変わるのは英語名だけ(追加 0 / 削除 0)であること。合格したら `git restore -- data/municipalities` で generated_at だけの差分を戻す
- `npm test`、`npm run lint`、`npm run build`
- ローカルの画面(preview_start の dev、375px 幅、英語モード)で、その市の一覧と詳細を見る。長い英語名で崩れない、横スクロールが出ない、英語で検索して当たる
- 日本語の検索は英訳を足しても変わらない(英語は語単位で別に照合している。`docs/tech-stack.md` §4)

## 5.5 Codex CLI の二重チェック

検証を終えてコミットしたあと、PR を作る前に、別のモデルにも読ませる(`docs/tech-stack.md` §18)。

```
npm run codex-review -- --items-en    # バックグラウンドで実行。5〜10分。その間ブランチを切り替えない
```

- サブエージェントの読み直しは「訳した市の一覧」を見る。Codex は生成データ全体を見るので、**共通辞書の訳が他市の同名の品目に付いたときの食い違い**(その市では区分の違う似た品目がある、注意点が対象を広げている)と、**すでに英訳のある別の品目と同じ訳になっていないか**を拾える(須賀川市で6件。「モニター」「ワイヤー/針金」など)
- 指摘はそのまま信じず、生成データ(品目名・区分・注意点)で確かめて本物だけ直す。他市で食い違う訳は、共通辞書から外して訳した市の辞書へ移し、「要確認」にする(その市の番で、その市の区分を見て訳す)
- 直したらコミットして、もう一度読ませる。結果は PR のコメントに残し、Kaz への報告に「Codex の指摘 ○件、対応 ○件」と1行添える
- Codex が使えないとき(未ログイン・利用枠切れ)は省いて、省いたことを報告に書く

## 6. PR と Kaz のレビュー

```
npm run items-en -- review <slug>    # 要確認の一覧 work/items-en/<slug>.review.md
```

PR を作り(`gh pr list` で、同じファイルを触る開いている PR が無いか先に見る)、CI と Vercel の緑を確認する。Kaz には要確認の一覧を渡し、とくに判断がほしい品目を報告に書き出す。Kaz の指摘を反映して緑を確かめてから、マージボタン(`gh pr merge <番号> --merge --delete-branch`)を渡す。

マージボタンを渡す直前に `git fetch` して、main が進んでいたら取り込む(`git merge origin/main`)→ `npm run build-data -- --all` → `npm run items-en -- bump` → 変わった市の items.json と municipality.json をコミット。英訳の PR を出しているあいだに自治体の追加やデータの修正が main に入ると、共通辞書の訳がその市にも付くので、取り込まないと CI の再現性の検査が落ちる。

## 7. 本番確認と記録(Kaz がマージしたあと)

- 本番の `/data/<slug>/search.json?v=<新しい版番号>` が main のデータと一致すること。内部ブラウザのモバイル表示で英語モードの画面を見る
- `docs/roadmap.md`「品目名の英訳の追加」の表と、記憶ファイル items-en-translation-trial の「進み具合」を更新する(記録は次の PR に含めてよい)
- 市への確認事項(意味が確定できなかった品目)を記憶ファイルに残す
- セッションの使用率を見て、60%を超えていたら引き継ぎメモを書いて切り替える

## 守ること

- 品目名(日本語)・区分・注意文言は変えない。「収集しません」等の注意文言は英訳の有無に関係なく出る
- 市のサイトへはアクセスしない(キャッシュだけで作り直す)
- 1回の PR で複数の市をまとめて訳さない(レビューと検査の単位を小さく保つ)
